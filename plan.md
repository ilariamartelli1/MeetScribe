# MeetScribe: incremental delivery plan

## What we are building

MeetScribe is a local, Dockerized meeting assistant for synthetic or explicitly authorized, non-sensitive test recordings. It starts as a **usable transcription tool**, then gains anonymous speaker labels, evidence-linked draft minutes, saved meetings, and longer recordings. The final local MVP accepts WAV/MP3 meetings up to 30 minutes and 500 MB; creates a timestamped, editable transcript; produces topics, decisions, action items, owners and deadlines; supports review and TXT/JSON export; and deletes application-managed meeting data after the agreed retention period. English is the default recording language, with Italian selectable. Code, comments, UI text, and developer documentation are in English.

The first usable release is deliberately smaller: a localhost browser page uploads a WAV/MP3 recording of at most **5 minutes / 100 MB**, shows an editable timestamped transcript, can cancel a running job, and downloads a clearly labeled **DRAFT / UNREVIEWED** TXT file. No diarization, summarization, accounts, saved meetings, or Ollama service is needed to use it. The audio is removed when processing ends or is cancelled; the result is temporary and edits are lost on refresh/restart. In-memory results expire after a short, documented session period (start with one hour). This is a useful first product, not a claim that the final meeting-minutes requirements are complete.

## Delivery rule: one small change per prompt

- Each numbered slice below is **one human-reviewable implementation request**, not an entire sprint. When asked to "start" or "continue," implement only the next unfinished slice, including its automated tests, the smallest relevant test run, and the matching README/plan update. Stop and explain what changed, why it is designed that way, and what the tests establish. Do not silently proceed to another slice or sprint.
- Leave each tested change **uncommitted for human review**. Do not start another slice while the previous change awaits approval; first address requested revisions or obtain explicit approval. On approval, commit and push only that approved change to GitHub. Keep each commit scoped to its reviewed, tested behavior. Never commit tokens, meeting recordings, model weights, database files, or local configuration. Small, explicitly generated synthetic audio fixtures may be versioned for tests.
- Keep slice IDs stable and record completed checkpoints in this plan as they are verified. Fakes and small fixtures test contracts in CI; any slice introducing a model also requires an explicit local real-model smoke check before calling its checkpoint complete. If hardware/setup blocks that check, report the checkpoint blocked rather than claiming success.
- A new code path needs a relevant test in the same slice. Prefer unit/API tests first, add browser or Docker tests where the behavior crosses those boundaries, and use only authorized, non-sensitive audio for real-model checks. Quality thresholds for WER/DER and correction time are set **after** measuring a baseline, not guessed ahead of time.

## Architecture choices and why

- **Keep the system small.** Python/FastAPI serves a versioned JSON API (`/api/v1`) and plain HTML/CSS/JavaScript. Use one API process with a bounded coordinator and a stoppable child process for each inference job; this keeps the browser responsive and permits real cancellation without leaving a native model call running. Do not start a new GPU job until the old child and any local model-server request have stopped. No broker, distributed worker fleet, vector database, agent framework, or React dependency for the local MVP. A later React client can consume the same API.
- **Introduce replaceable model boundaries only as they are used.** Define typed, framework-independent transcript segments, diarization turns, and minutes. Add ASR, diarization, and summary adapters when their respective sprints begin; retain model/version/settings provenance in results. Compare alternatives on the same fixtures, not model file size alone. For the first release, try faster-whisper `large-v3-turbo` on a tested INT8-compatible GPU compute setting; reject unavailable CUDA with an actionable error. CPU mode must be an explicit, tested choice, never a silent fallback.
- **Do not filter twice or change the timebase without accounting for it.** Start with faster-whisper's integrated Silero VAD rather than a second independent VAD pass. Use conservative settings and tests for quiet negations and silence. Preserve timestamps on the original recording. Later, pyannote independently processes the audio (not the transcript); align its speaker turns to ASR timestamps afterward. Run heavy GPU stages sequentially on this 6 GB VRAM laptop.
- **Package for portability, not premature production.** Docker Compose initially runs only the app. Add an internal-only Ollama service when minutes generation exists; publish only the app to host `127.0.0.1`, not Ollama. Bind correctly inside containers, validate Host/Origin and protect state-changing requests against cross-site submission; use local persistent volumes only when storage is introduced. Docker moves software, not GPU drivers, credentials, authorization, security policy, or operating capacity: company-VM deployment and real company recordings require separate approval and work. "Voice 1" labels are not anonymization or recording consent.
- **Keep inference on premises.** Downloads of pinned weights are allowed during separate provisioning, but no audio/transcript goes to third-party inference. Restrict runtime adapters to pinned local model paths and the explicitly allowlisted internal Ollama endpoint (`http://ollama:11434`); reject configurable remote endpoints instead of trusting a URL supplied by a client. Keep setup tokens out of images and runtime configuration. Verify the pinned versions support and use cloud/telemetry-off and offline settings (including `OLLAMA_NO_CLOUD=1`, `PYANNOTE_METRICS_ENABLED=0`, `HF_HUB_DISABLE_TELEMETRY=1`, and `HF_HUB_OFFLINE=1` when applicable). A private Docker network alone is not an egress firewall: run a post-provisioning job with outbound traffic blocked before claiming offline operation.
- **Limit browser retention.** Return `Cache-Control: no-store` on transcript, meeting, audio and export responses; do not put content in localStorage, IndexedDB, service workers, or external CDNs. Keep scripts/assets local, enforce a restrictive content-security policy, render model text as text rather than HTML, and clear temporary browser media URLs when no longer needed. Browser downloads and host backups remain outside app deletion control.
- **Pin, then update deliberately.** Lock transitive Python dependencies, container image digests and model revisions/digests, with a record of licenses and compatible CUDA/audio-library versions. Check security advisories and licenses at each release checkpoint and before company deployment; update a dependency/model in its own reviewed slice, then rerun the affected tests, Docker smoke check and real-model quality check. Do not use unattended `latest` upgrades or assume pinning alone is maintenance.
- **Make uncertain outputs visibly uncertain.** Anonymous speakers are not identified people; overlap can be marked unknown. A JSON schema and a real source ID prove neither factual support nor completeness. Minutes are drafts until reviewed; owners/dates not explicitly supported stay "not specified," and relative dates are not silently resolved using upload time. Bind citations to the exact transcript revision; transcript edits mark generated minutes stale, and regeneration is deliberate. Do not overwrite human edits or present stale material as reviewed.

## Sprint 0 - Runnable shell and ASR feasibility

**0.1 Minimal application (committed).** Create the Python package, a FastAPI health endpoint, minimal configuration, a small test suite, formatting/type-check commands, and pinned Python dependencies. Add the actual local run/test commands to README. *Check:* tests pass and the health endpoint responds; no model download is needed yet.

**0.2 Local container (implemented and verified).** Dockerize that application for Linux; make GPU mode an explicit preflight and CPU test mode explicit, publish only on host loopback, and avoid baked-in weights/secrets. Verify the Linux host driver and NVIDIA Container Toolkit expose the GPU inside the container, without assuming that this proves CUDA inference works. *Check:* the CPU container health endpoint and loopback binding have been verified; the GPU container detects the RTX 4050 and its health endpoint responds. CUDA inference remains a separate check in slice 0.3.

**0.3 Model feasibility before building the UI (implemented and verified).** Pin the exact Linux driver, container image, CUDA/cuDNN, Python, CTranslate2, faster-whisper, PyAV/audio decoder and ASR model revisions that work together; document the model download/provisioning command. In the actual app container, decode a tiny WAV and MP3 and perform GPU inference, not just model loading. Record requested and effective compute type, per-stage elapsed time, peak GPU VRAM and host/container RAM, and memory remaining after unloading; repeat the job to catch retained allocations. *Check:* two offline GPU jobs transcribed synthetic WAV and MP3 samples, and missing model/GPU checks failed explicitly. The tested stack and sampled measurements are recorded in README; longer recordings and transcription quality remain unverified. If a later representative workload does not fit, evaluate a smaller compatible model through the same intended ASR boundary before committing the UI to it.

## Sprint 1 - First usable release: short transcripts

**1.1 Timestamped ASR contract (committed).** Add a typed ASR adapter and service returning original-audio timestamped segments for English or Italian; use one conservative VAD path, keep transcription distinct from translation, and reject empty/no-speech results honestly. *Check:* fake-model tests cover silence, short negations at speech boundaries, errors and invalid timestamps. The real offline GPU smoke recognized quiet synthetic "no/not/non" utterances after silence in both languages and rejected silence; no reference negations were missed. These small fixtures do not establish overall transcription quality or word-level timestamp accuracy.

**1.2 One responsive temporary job (implemented; awaiting review).** Implement an in-memory single-job coordinator outside the HTTP event loop; run inference in an owned child process so cancellation can actually stop native work. Expose status/result/error with a one-hour result lifetime; reject new work while busy. Retain at most 16 results; if full, require explicit confirmation of the oldest result before replacing it. Shutdown/restart loses temporary results by design and stops its child. *Check:* fake-model tests cover status polling during work, failure, expiry, concurrency, capacity, child cleanup and shutdown; an offline GPU smoke exercises the real adapter in a spawned child. Confirmation UI and temporary-audio cleanup remain later slices.

**1.2a Cancel a running job (implemented; awaiting review).** Add a cancel endpoint/state (`cancelling` then `cancelled`) and cancel control in the browser in slice 1.4. Terminate only the owned child; if it does not exit within a bounded wait, stop that specific child process, then discard any late result before accepting another job. Report already-finished/unknown jobs clearly; cancellation is not a request to delete an already exported transcript. *Check:* fake jobs cover cancellation during model load and inference, a late result, repeated cancel, forced termination, retry after a termination error, freed job slot and responsive status requests. Existing audio paths are caller-owned; generated temporary files and their cleanup are introduced in slice 1.3.

**1.3 Bounded upload endpoint.** Stream WAV/MP3 into a generated temporary path; bound multipart parts/request bytes, duration (5 minutes), size (100 MB), decoder time, decoded samples and supported channels; reject corrupt/empty/unsupported files before starting work. Expose result-capacity errors and explicit confirmation of the oldest result without starting a worker before confirmation. Delete temporary audio after completion, cancellation or failure, do not retain transcript text in logs, and reject unintended origins/state changes. Set `Cache-Control: no-store` on status, transcript and download responses from the start. *Check:* valid mono audio, stereo with speech only on the left or right, and opposite-phase channels; preserve the audible speech or reject an unsupported layout clearly rather than silently losing it. Also test missing length, oversize, misleading media, multipart abuse, invalid audio, decoder timeout, cross-origin requests, paths, response headers, capacity confirmation and cleanup with fake inference.

**1.4 Minimal browser flow.** Add an accessible plain-JS page for language choice, upload/status/errors, a Cancel button, editable timestamped segment text and client-side TXT draft download. When result capacity is full, ask whether to replace the oldest result; declining must not start a job. State at upload that only synthetic or explicitly authorized non-sensitive test audio is permitted and that speaker labels do not anonymize the recording. Render transcript text safely; do not retain it in browser storage or promise audio playback or saved edits yet. Use a restrictive content-security policy and local-only assets. *Check:* browser/API test for upload -> edit -> download, cancel during processing, accepting and declining result replacement, visible recording-use notice, failure display, draft labeling, safe rendering and no persistent browser content.

**1.5 First-release checkpoint.** Run the Docker flow on authorized non-sensitive WAV and MP3 samples in English and Italian, including a representative five-minute file, from a provisioned offline model. *Check:* use human-annotated fixtures with quiet negations, proper names, numbers/amounts, spoken dates and speech after multiple silences; record each raw-transcript mismatch by type and verify the operator can correct it in the TXT export. Check ASR segment times against annotated events on the original audio; cancel a real run and confirm the worker exits and GPU memory/job slot are released; verify the README's setup, run and test commands work. **A user can now obtain, correct and cancel a local draft transcript.**

## Sprint 2 - Speaker-labeled transcript

**2.1 Diarization setup.** Accept Community-1's access conditions and provision pinned model artifacts once using a scoped Hugging Face setup token, then remove the token from runtime. Record license/attribution, dependent weights, exact local paths and the tested PyTorch/TorchCodec/FFmpeg versions alongside the existing CUDA/CTranslate2 stack. Start inference on CPU to avoid ASR GPU contention; bound CPU threads and container memory with headroom for the Linux desktop, decode once where possible and release intermediate buffers. *Check:* decode WAV/MP3 and run real ASR followed by real diarization in the same provisioned app image, then repeat; measure per-stage host RAM/swap, peak VRAM, CPU/GPU placement and memory after each stage under normal desktop load. A pyannote install that breaks ASR or audio decoding blocks this checkpoint; absent/incomplete caches fail clearly.

**2.2 Speaker-turn adapter.** Add a typed diarization adapter operating on original audio independently of ASR. Keep exclusive turns and ordinary overlap evidence; reject or explain unsupported stereo layouts rather than silently losing a speaker. *Check:* fake-model fixtures for turns, overlap, errors and channels; a real two-speaker smoke test.

**2.3 Align timestamps.** Match diarization turns to transcript segments on the original audio timebase. Assign stable per-meeting "Voice 1/2" labels and allow unknown attribution. *Check:* unit fixtures for joins, boundaries, similar/overlapping/short turns, and events after several silent gaps; assert aligned turns remain ordered, within the original duration and attached to the annotated speaker/event rather than a silence-compacted timestamp.

**2.4 Edit and export speakers.** Add speaker labels and correction to the temporary browser transcript and TXT export. *Check:* browser test for correcting text/speaker and an end-to-end English/Italian smoke with speaker turns. **The tool now yields a reviewable speaker-attributed transcript.**

## Sprint 3 - Draft structured minutes

**3.1 Private local summary model.** Add the internal-only Ollama Compose service and provision a pinned, license-checked quantized Qwen3 4B Q4 artifact if it fits. Record the Ollama image/model digest and tested runtime settings alongside the ASR/diarization compatibility matrix. *Check:* container connectivity only from the app, short real-model smoke and an offline run; inspect whether model layers and context cache use GPU or spill into host RAM, and reject an unavailable model without remote inference.

**3.2 GPU handoff.** Serialize ASR, all summarization/regeneration requests, and model handoffs; configure Ollama for one active request/model, set `keep_alive` to unload after generation, and confirm the model is released before the next ASR job. If a summary is cancelled, stop its request, verify Ollama is no longer processing and release its model before another GPU job starts. *Check:* repeat the real ASR -> CPU diarization -> Ollama -> ASR sequence in the final containers, including concurrent regeneration and a cancelled generation, and record per-stage time, peak/post-stage VRAM, peak host RAM, swap and actual CPU/GPU placement under ordinary desktop load. A successful first job is not enough: if the next job OOMs, unexpectedly offloads, or slows sharply, adjust model/context/worker lifetime and rerun before claiming the combined pipeline fits.

**3.3 Minutes schema and evidence checks.** Define typed topics, summary, decisions and action items with source-segment IDs and the versioned export contract below. Keep an explicitly named owner separate from an anonymous speaker reference. Preserve deadline wording; for the MVP, never normalize relative dates such as "next Friday" (and never substitute upload time). Set `deadline_date` only for an unambiguous absolute calendar date explicitly supported by the transcript. Validate response shape, citation IDs and completeness separately from model output. *Check:* fake-model tests for malformed JSON, unsupported IDs, incomplete results, "I"/"we", named nonparticipants, absent/ambiguous dates and uploaded-later recordings; do not treat a valid citation as proof the claim is true.

**3.4 Bounded extraction.** Add the summary adapter and prompts for short transcripts. Configure Ollama's actual context size from a measured GPU-memory budget, not the model's advertised maximum or an implicit runtime default. Count instructions, chat-template overhead, output schema, transcript text/IDs/timestamps and reserved output (including any thinking tokens) with the model tokenizer or a verified conservative bound. Disable thinking through a tested runtime control if appropriate. Before overflow, split the input or fail explicitly; reject incomplete/length-stopped responses, validate only the final answer and compare runtime token counts with the budget. Treat proposals, negations, changes of deadline, unknown speaker identity and recorded instructions as untrusted evidence, not commands or automatic facts. *Check:* just-below/above-budget fixtures with distinct actions at the beginning, middle and end, plus fake-model tests for truncation, unsupported claims, adversarial quoted text and model failure. The five-minute release cannot claim complete minutes unless all its segments were processed.

**3.5 Edit and export draft minutes.** Show and allow editing of minutes, source segments and uncertainty; export matching TXT and versioned JSON following the contract below. TXT and JSON both conspicuously identify **DRAFT / UNREVIEWED** versus **REVIEWED** from the saved revisions; a draft can be downloaded immediately. *Check:* API/browser tests for edits, safe text rendering, Italian Unicode round trips, missing/relative dates, revision/status changes and TXT/JSON consistency.

**JSON export v1 contract (implemented in 3.3 and 3.5).** UTF-8; `schema_version` is `1`; `meeting_id` is the temporary job ID until persistent meeting IDs arrive in Sprint 4; `language` is `en` or `it`. `start_ms`/`end_ms` are integer milliseconds on the original recording timeline, with `0 <= start_ms < end_ms <= duration_ms`. Segment IDs are stable within a transcript revision; citations use those IDs. A nullable `speaker_id` means attribution is unknown. `review_status` is `"DRAFT / UNREVIEWED"` or `"REVIEWED"`; edits invalidate review of the affected transcript/minutes revision pair, and `stale` indicates that the minutes were generated from a different transcript revision. These status and revision fields must be computed from the same authoritative state as the exported contents, never supplied by the LLM.

```json
{
  "schema_version": 1,
  "meeting_id": "meeting-123",
  "language": "en",
  "review_status": "DRAFT / UNREVIEWED",
  "stale": false,
  "transcript_revision": 1,
  "minutes_revision": 1,
  "minutes_source_transcript_revision": 1,
  "segments": [
    {
      "id": "segment-1",
      "start_ms": 1000,
      "end_ms": 2500,
      "speaker_id": "voice-1",
      "text": "I'll send it next Friday."
    }
  ],
  "minutes": {
    "summary": "...",
    "topics": [{"text": "...", "source_segment_ids": ["segment-1"]}],
    "decisions": [{"text": "...", "source_segment_ids": ["segment-1"]}],
    "action_items": [{
      "description": "Send it",
      "owner_name": null,
      "owner_speaker_id": "voice-1",
      "deadline_text": "next Friday",
      "deadline_date": null,
      "source_segment_ids": ["segment-1"]
    }]
  }
}
```

`owner_name` is a person explicitly named in the recording; `owner_speaker_id` is an anonymous speaker only when attribution is supported, never an inferred real identity. `deadline_text` retains the source wording; `deadline_date` is an ISO `YYYY-MM-DD` date only when unambiguous. For no spoken deadline both are `null`; for an ambiguous/relative deadline only `deadline_date` is `null`. Unknown owners likewise use `null`, displayed as "not specified" in the UI. Arrays may be empty, but required keys remain present. Before JSON export is implemented, test schema validation, null semantics, original-audio time units, cited revision integrity and round trips; changing these fields later requires a new `schema_version`. Reject unsupported export versions clearly; if importing old versions is added later, use an explicit, tested migration rather than silently reinterpreting their fields.

**3.6 Deliberate regeneration.** Mark minutes stale after transcript edits and regenerate only on request, without silently overwriting manual edits. *Check:* concurrent edit, stale-citation, failed-regeneration and no-overwrite tests.

**3.7 Minutes checkpoint.** Compare generated English/Italian decisions/actions with small human-checked references and record critical errors, correction time and end-to-end resources. *Check:* real offline Docker run from audio through corrected draft; never assert that schema/citations eliminate hallucinations. **A user now has a complete, explicitly unreviewed meeting draft.**

## Sprint 4 - Saved meetings, audio review and honest retention

**4.1 Persistent meeting records.** Introduce SQLite migrations, local audio/results volumes, meeting IDs and model provenance. Save audio and drafts across restarts from this point forward; temporary-session results from earlier releases are not migrated. Keep the DB on a local persistent volume: enable WAL and `synchronous=FULL` for durable commits, `foreign_keys=ON` and a bounded `busy_timeout` on every connection; use connections owned by one execution context, short transactions outside inference, and versioned migrations that reject an unsupported newer schema. No live-file-copy backups. *Check:* save/restart/reload/migration tests, concurrent reads/writes, lock timeout and disk-full errors, and proof recordings remain outside the web root.

**4.2 Persistent worker ownership.** Use a single Uvicorn API process (no multiworker or auto-reload in Docker) and take a nonblocking, exclusive Linux file lock in the same local data volume at startup; a second app instance sharing that volume fails startup clearly. Atomically claim SQLite jobs by status/attempt ID, so a stale attempt cannot publish after restart; release the file lock automatically on process exit. Define bounded retries only for identified transient failures; mark non-retryable errors failed. Publish staged artifacts using temporary names and atomic rename, reconcile orphaned files on startup, and checkpoint job state at stage boundaries without a transaction held during inference. Never restart an attempt until its former owner is confirmed gone. *Check:* launch two app instances against one volume; inject interruption immediately before/after artifact rename and DB commit, transient/permanent failures, and crash/restart during each stage. Verify no duplicate GPU job, stale publication, partial complete state or leaked orphan; keep status responsive.

**4.3 Revisions and conflicting edits.** Tie minutes/citations to a specific transcript revision; use optimistic save checks and attempt IDs to reject stale browser edits and late results after deletion, cancellation or regeneration. *Check:* two-tab, cancel/delete-during-inference and edit-during-generation tests, including no overwrite of human work.

**4.4 Delete and expire.** Add manual delete plus cleanup at startup and every hour while the app runs. Expiration is seven days from upload, not last edit: deny access on **every** meeting detail, playback, export and worker-resume path as soon as expired, even before cleanup has finished; then remove all application-managed files and revisions with visible retryable cleanup errors. A powered-off machine cannot erase files at the exact deadline; downloaded exports, SQLite free pages and host backups are not forensically erased by app deletion. Do not create app-managed archival backups for this test-only MVP. Inventory audio, playback derivatives, temporary uploads, transcript/minutes revisions, failed-job artifacts, logs and browser caches; remove managed copies and evaluate SQLite secure-delete/WAL checkpoint behavior, without promising forensic erasure. *Check:* use a fake clock for expiry during work, a missed cleanup interval and restart after expiry; assert all access routes deny expired content before cleanup. Seed unique synthetic markers and inspect managed files, DB/WAL and logs after deletion and interrupted cleanup; surface and retry any cleanup failure.

**4.5 Storage and queue admission.** Cap outstanding jobs, total app-managed storage and reserved free space before accepting work; prevent repeated clicks from duplicating jobs. *Check:* full-queue, quota and low-disk rejection, partial-file cleanup, and continued access to review/delete.

**4.6 Revision-bound review and playback.** Offer playback by meeting ID with verified seeking, transcript/minutes edits, explicit review of the current revision, and TXT/JSON exports derived from the same saved state. Define a supported browser/audio profile (tested browser versions, WAV encodings and MP3 variants); if decoding succeeds but the browser cannot play an input, provide a verified local playback derivative or reject it explicitly. Serve audio through meeting-ID lookup with byte-range support, never arbitrary paths. Any edit or regeneration invalidates prior review. *Check:* `206` and invalid-range responses, playback of each advertised codec/browser combination, and clicks on segments near the start, after several pauses and near the end; confirm the expected spoken event is audible at the linked time, including any MP3 encoding offset. Also test reviewed-then-edited, stale citations, restart, draft/reviewed export and the browser journey. **Meetings can now be revisited, corrected and deleted.**

## Sprint 5 - Full local MVP and measured quality

**5.1 Complete-transcript minutes.** Re-measure the actual Ollama context and output budget for longer recordings. Extract from bounded chunks of the original segment stream if needed, merge evidence while respecting later amendments/retractions, and reject incomplete output instead of dropping the beginning or end. *Check:* just-below/above-limit and chunk-boundary fixtures with distinct early/middle/late decisions, revised deadlines and source revision integrity; no export marked complete unless every chunk is accounted for.

**5.2 Longer inputs with measured limits.** Raise admission limits to 30 minutes / 500 MB only after repeating full-pipeline resource checks; bound decoding, temp storage and total queued data. Preserve original timestamps and supported browser playback for MP3/WAV. *Check:* long, malformed, stereo, quiet, mixed-language and low-disk cases; visible errors rather than an implicit CPU or success-shaped fallback.

**5.3 Evaluation baselines.** Build a small authorized, non-sensitive English/Italian reference set; report WER with a documented case/punctuation/number-normalization policy, DER (with declared overlap/collar settings), factual support/precision/recall for decisions/actions, owner/date errors, citation validity, manual correction time **versus writing minutes manually on equivalent material**, processing time and peak VRAM/RAM. Break out errors for quiet negations, proper names, numbers/amounts and spoken dates; report channel-dependent failures and playback-to-transcript seek offsets separately from aggregate WER. Establish baselines first, then agree numeric quality and timing gates and put reproducible checks in the project. *Check:* document raw error counts and a held-out acceptance set with representative audio and exact model versions; do not treat a valid citation ID as proof of factual support.

**5.4 Full local MVP checkpoint.** Verify repeated 30-minute Docker runs and post-provisioning inference without outbound access. Review pinned runtime/model advisories and license inventory before the checkpoint. *Check:* report end-to-end and per-stage elapsed time, peak GPU VRAM, host RAM/swap, CPU/GPU placement and post-stage release on the actual Linux laptop under normal desktop load; reproduce the README's exact version matrix and commands. Confirm no cloud/telemetry or content-bearing browser caches, cancellation releases the worker and GPU, unsupported hardware fails clearly, and logs contain no meeting content. **This is the complete local MVP, not approval for real company data.**

## Later experiments and company deployment (not blockers for the first usable release)

- Benchmark whisper.cpp Q3 against faster-whisper INT8 on identical recordings and settings; optionally compare WhisperX end-to-end and aTrain's review workflow. Add another adapter or forced alignment only if measured accuracy, timestamps, speed or learning value justifies it. Avoid claiming a Q3 file works with CTranslate2 or that smaller weights guarantee faster inference.
- Improve UI, supported audio layouts, speaker-correction ergonomics and larger/longer meeting handling based on observed failures; do not build a second pipeline speculatively.
- Before a move to a company-controlled VM or real meetings, obtain authorization, confirm VM GPU/CPU capacity and model licenses, implement authentication/authorization, transport security, approved storage/backups and operational retention, and re-evaluate multiuser worker ownership. Container portability alone does not satisfy those requirements.

## README contract

Keep `README.md` short and accurate: a brief description and current capability, followed by **all verified commands needed for the current runnable checkpoint**. At the relevant slice, document supported Linux/NVIDIA and Docker requirements, tested Python/CUDA/cuDNN/CTranslate2/PyTorch/pyannote/Ollama versions, dependency lock and exact model source/revision/quantization or digest, license/consent, model-download commands, secret-safe provisioning, CPU/GPU selection, Docker startup/shutdown, test/lint commands, offline verification, data directories, and deletion. Update it with each new model/dependency/command. Before code exists, say explicitly that the app is not yet runnable rather than inventing versions or copy-paste commands that do not work.
